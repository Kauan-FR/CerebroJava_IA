## O que é

Técnica de modelagem voltada para **análise**, não para transação. Organiza os
dados em **fatos** (métricas) cercados por **dimensões** (contexto), otimizando
consulta em vez de gravação.

Proposta por **Ralph Kimball**. Base do data warehouse e dos cubos OLAP.

---

## OLTP × OLAP ⭐

> [!danger] Par que a banca inverte — cobrado quase sempre

| | **OLTP** | **OLAP** |
| --- | --- | --- |
| Nome | Online **Transaction** Processing | Online **Analytical** Processing |
| Finalidade | Operação do dia a dia | Análise e apoio à decisão |
| Operação típica | `INSERT`, `UPDATE`, `DELETE` | `SELECT` com agregação |
| Modelagem | **Normalizada** (3FN) | **Dimensional** (desnormalizada) |
| Dado | Atual, detalhado | Histórico, consolidado |
| Volume por consulta | Poucas linhas | Milhões de linhas |
| Usuário | Operacional, muitos simultâneos | Analista, gestor, poucos |
| Otimizado para | **Escrita** | **Leitura** |
| Redundância | Mínima | Aceita de propósito |

**Mnemônico:** T de **Transação** = operação · A de **Análise** = decisão

## Componentes

### Tabela fato

Guarda as **métricas** do negócio. A PK é composta pelas FKs das dimensões.

Vendas (ID_Produto, ID_Cliente, ID_Tempo, ID_Loja,  
quantidade, valor_venda, desconto)


Características: muitas linhas, poucas colunas, cresce sem parar.

> [!warning] Fato ≠ tabela associativa
> A associativa resolve N:M e não tem métrica. A fato **existe para guardar métrica**.
> Só a PK composta pelas FKs é análoga.

### Tabela dimensão

Guarda os atributos **descritivos** que dão contexto ao fato — servem para
filtrar, agrupar e rotular.

Produto (ID_Produto, nome, categoria, marca, departamento)


Características: poucas linhas, muitas colunas, **desnormalizada de propósito**.

> [!note] Chave substituta
> As dimensões usam **surrogate key** gerada pelo DW, não a chave do sistema de
> origem. Isso permite guardar histórico quando o dado de origem muda (SCD Tipo 2)
> e isola o DW de mudanças na origem.

### Dimensão tempo

**Sempre existe** em um modelo dimensional, e é uma tabela física — nunca
calculada em tempo de consulta. Guarda dia, mês, trimestre, ano, dia da semana,
feriado, dia útil.

### Granularidade ⭐

**O nível de detalhe de uma linha da tabela fato.**

- Grão fino (atômico) = uma linha por item de venda → mais flexível, mais volume
- Grão grosso = uma linha por mês/loja → menos volume, análise limitada

> [!warning] Regra de Kimball
> Definir o **grão é a primeira decisão** do projeto, antes de escolher dimensões
> e fatos. Prefira sempre o grão mais **atômico** possível — não dá para
> desagregar depois.

### Dimensionalidade

As perspectivas pelas quais o fato pode ser analisado. Cada dimensão é um eixo
do cubo.

## Tipos de métrica ⭐

| Tipo | Soma em quais dimensões | Exemplo |
| --- | --- | --- |
| **Aditiva** | **Todas** | valor de venda, quantidade |
| **Semiaditiva** | Todas **menos tempo** | saldo em conta, estoque |
| **Não aditiva** | **Nenhuma** | percentual, margem, razão |

Saldo de conta em janeiro + saldo em fevereiro **não faz sentido** — por isso
semiaditiva. Percentual nunca se soma; recalcula-se a partir dos componentes.

## Os três esquemas ⭐

### Star schema (estrela)

Fato central + dimensões **desnormalizadas**, cada uma ligada diretamente ao fato.

```
			Tempo
			|
Cliente — FATO — Produto  
			|  
			Loja
```

| Vantagem | Desvantagem |
| --- | --- |
| Menos joins → consulta rápida | Redundância nas dimensões |
| Simples de entender | Mais espaço |

### Snowflake (floco de neve)

Extensão do estrela, com as **hierarquias das dimensões normalizadas** em
subtabelas.

Produto → Categoria → Departamento

| Vantagem                        | Desvantagem                          |
| ------------------------------- | ------------------------------------ |
| Menos redundância, menos espaço | **Mais joins → consulta mais lenta** |
| Facilita hierarquias complexas  | Mais complexo de entender            |
| Consistência na atualização     |                                      |

### Constellation / Fact Constellation (Galaxy) ⭐

**Múltiplas tabelas fato compartilhando dimensões.** É o que faltava.

FATO_Vendas — Produto — FATO_Estoque  
\ Tempo /


As dimensões compartilhadas chamam-se **dimensões conformadas** — mesma definição,
mesma chave, usadas por vários fatos. É o que permite comparar métricas entre
processos de negócio diferentes.

Um data warehouse corporativo é, na prática, uma constellation.

| Esquema | Dimensões | Fatos |
| --- | --- | --- |
| **Estrela** | Desnormalizadas | Um |
| **Floco de neve** | Normalizadas | Um |
| **Constellation** | Compartilhadas (conformadas) | **Vários** |

## Slowly Changing Dimensions (SCD) ⭐

Como tratar mudança em atributo de dimensão — o cliente mudou de cidade.

| Tipo | O que faz | Histórico |
| --- | --- | --- |
| **Tipo 0** | Nunca muda | — |
| **Tipo 1** | **Sobrescreve** o valor antigo | **Perde** |
| **Tipo 2** | Cria **nova linha** com nova surrogate key + data início/fim + flag de ativo | **Preserva** |
| **Tipo 3** | Cria **nova coluna** (`cidade_atual`, `cidade_anterior`) | Guarda só o anterior |

**Tipo 2 é o mais usado** — é o que permite analisar as vendas com a cidade que
o cliente tinha na época.

## Operações OLAP ⭐

| Operação | O que faz |
| --- | --- |
| **Drill-down** | **Desce** na hierarquia — ano → trimestre → mês. Mais detalhe |
| **Roll-up** (drill-up) | **Sobe** na hierarquia — mês → ano. Consolida |
| **Slice** | Corta **uma** dimensão fixando um valor — só o ano 2026 |
| **Dice** | Corta **várias** dimensões — ano 2026 **e** região Nordeste |
| **Pivot** (rotação) | Gira o cubo, troca linhas por colunas |
| **Drill-across** | Consulta **dois fatos** pelas dimensões conformadas |
| **Drill-through** | Vai do agregado até o dado **detalhado na origem** |

> [!danger] Par que a banca inverte
> **Drill-down = desce, detalha** · **Roll-up = sobe, consolida**
> **Slice = uma dimensão** · **Dice = várias dimensões**

### Tipos de armazenamento OLAP

| Sigla | Armazena em | Característica |
| --- | --- | --- |
| **ROLAP** | Relacional | Escala melhor, mais lento |
| **MOLAP** | Cubo multidimensional | Mais rápido, limitado em volume |
| **HOLAP** | Híbrido | Detalhe no relacional, agregado no cubo |
