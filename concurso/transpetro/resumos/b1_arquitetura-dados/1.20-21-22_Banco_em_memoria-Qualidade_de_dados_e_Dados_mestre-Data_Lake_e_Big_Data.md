## 1.20 Banco em memória (in-memory)

SGBD que armazena e processa os dados **principalmente na RAM**, em vez de disco.

| Casos de uso | |
| --- | --- |
| Velocidade extrema | Acesso em micro/milissegundos |
| Análise em tempo real | Milhões de transações/segundo para decisão imediata |
| Cache e sessões | Carrinho de compras, placar de jogo. Ex.: **Redis** |
| IoT | Fluxo contínuo de sensores |

> [!warning] O trade-off — cai na prova
> RAM é **volátil**: perde tudo se faltar energia.
> Para garantir durabilidade, o banco in-memory usa **snapshot** (cópia periódica ao
> disco) ou **log de transações**. Sem isso, não há durabilidade do ACID.
>
> E RAM é **cara e limitada** — não serve para volume gigante como o disco serve.

## 1.21 Qualidade de dados

Grau em que os dados são **confiáveis, precisos e úteis** para a decisão de negócio.

### As dimensões da qualidade ⭐

| Dimensão | Pergunta que responde |
| --- | --- |
| **Completude** | Faltam valores? Há campos vazios que deveriam estar preenchidos? |
| **Precisão / Acurácia** | O valor corresponde à realidade? |
| **Consistência** | O mesmo dado bate entre sistemas diferentes? |
| **Unicidade** | Há duplicatas do mesmo registro? |
| **Atualidade / Tempestividade** | O dado está atualizado? |
| **Validade / Conformidade** | Segue o formato e as regras esperadas? (CPF válido, data real) |
| **Integridade** | As relações entre os dados estão preservadas? |

### Técnicas

| Técnica | O que faz |
| --- | --- |
| **Data profiling** | Examina o dado real para achar problemas |
| **Data cleansing** (limpeza) | Corrige, padroniza, remove duplicatas |
| **Deduplicação** | Remove registros repetidos |
| **Validação** | Aplica regras na entrada |

## 1.21 Dados mestres (Master Data) ⭐

Os dados de **referência centrais**, compartilhados entre vários sistemas da
organização: **cliente, produto, fornecedor, funcionário, conta**.

> [!note] Dado mestre × dado transacional
> **Mestre** — entidades estáveis, reutilizadas. "Cliente Ana"
> **Transacional** — eventos, movimentos. "Pedido 500 da Ana em 03/09"
>
> O transacional **referencia** o mestre.

### MDM — Master Data Management

Disciplina que garante uma **fonte única de verdade** para os dados mestres.

Problema que resolve: o mesmo cliente cadastrado de três formas diferentes em três
sistemas (você viu isso na Q13 do 1.8 — Cliente, Comprador, Consumidor).

> [!warning] Ligação
> MDM é o `fonte-unica-de-verdade` no nível corporativo → [[fonte-unica-de-verdade]]
> "Dados de referência" também aparece como metadado → [[1-06-metadados]]

## 1.22 Data Lake

Repositório de dados **brutos**, no formato original (JSON, CSV, log, texto, imagem).

| | Característica |
| --- | --- |
| Esquema | **schema-on-read** — definido na leitura |
| Dado | bruto, como veio |
| Público | cientista de dados, engenheiro |
| Risco | sem governança, vira **data swamp** (pântano) |

### Data Lake × Data Warehouse ⭐

> [!danger] Par que a banca cobra

| | Data Warehouse | Data Lake |
| --- | --- | --- |
| Dado | tratado, modelado | bruto, original |
| Esquema | **schema-on-write** | **schema-on-read** |
| Processo | **ETL** | **ELT** |
| Formato | tabelas dimensionais | qualquer arquivo |
| Público | analista de negócio | cientista de dados |
| Custo | maior | menor |

### ETL × ELT ⭐

| | Ordem | Onde |
| --- | --- | --- |
| **ETL** | Extract → **Transform** → Load | transforma **antes** de carregar (DW) |
| **ELT** | Extract → Load → **Transform** | carrega bruto e transforma **depois** (data lake) |

> [!note] Data Lakehouse
> Arquitetura híbrida que junta a flexibilidade do lake com a estrutura do warehouse.
> Termo novo, pode aparecer.

## 1.22 Big Data

Volume de dados grande e complexo demais para ferramentas tradicionais.

### Os 5 Vs ⭐

| V | Significa |
| --- | --- |
| **Volume** | Quantidade massiva |
| **Variedade** | Tipos diversos (estruturado, semi, não estruturado) |
| **Velocidade** | Ritmo de geração e processamento |
| **Veracidade** | Confiabilidade do dado |
| **Valor** | Utilidade extraída |

> [!note] Os 3 Vs originais são Volume, Variedade, Velocidade
> Veracidade e Valor foram acrescentados depois. Algumas questões falam em "3 Vs".

### Ferramentas (só reconhecer)

Hadoop (armazenamento distribuído — HDFS), MapReduce (processamento), Spark
(processamento em memória, mais rápido que MapReduce).
