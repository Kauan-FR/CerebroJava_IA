## Modelo

Modelo é uma forma de organizar as informações que está na mente cliente, para que o desenvolvedor ele saiba o que tem que ser feito no desenvolvimento do banco

## Modelo de dados

É o processo de modelagem dos dados para um sistema de informação, onde todas as informações do cliente irão se transformar em atributos e colunas na tabela

## Modelo relacional

É uma tabela de banco de dados que conseguem se relacionar entre si.

## Componentes do modelo relacional

Os componentes desse modelo são as relações, os atributos que proporciona esse relacionamento

## Banco de dados relacional

Basicamente são tabelas que armazenam informações, e com isso essas informações são relacionadas

## Componentes do banco de dados relacional

- Tabela => Estrutura onde esta localizado todos os atributos e colunas que formam uma tabela
- Tuplas => São as linhas da tabela, onde estão armazenadas os dados do cliente.
- Colunas => Local onde se armazena um tipo especifico do dado, ou ela também pode não armazenar nada (valores nulos)
- Relacionamento => É a junção de duas tabelas através de dois atributos chamados chave primaria e chave estrangeira
- Outros => Índices, SP, Trigger etc ...
- Chave primaria => Atributo com o valor único que não se repete, muita das vezes gerado automaticamente pelo SGBD
- Chave estrangeira => Atributo derivado da chave primaria e utilizado para relacionar dois ou mais atributos

## Analise de requisitos

Face feita para analizar quais  dados serão armazenados no banco, quais dados serão descartados para não poluir o banco com informações desnecessarias. Essa face ela é extremamente importante para evitar redundancia de dados e o armazenamente de informações inuteis 

## Modelo entidade-relacionamento (MER)

Usado para ilustrar o relacionamento das tabelas, que posteriormente será gerado como um modelo grafico, que será mais simples de visualizar os relacionamentos

## Componentes do MER

- Entidade => Qualquer coisa que podemos retirar informações uteis
- Atributo => Algo que descreve uma entidade, que descreve as caracteristicas da entidade
- Relacionamento => A conexão de duas entidades através de dois atributos chaves (PK e FK)

# 1.3 O Modelo Relacional

## O que é

Modelo de dados proposto por **Edgar F. Codd (1970)**, baseado em **teoria dos
conjuntos e lógica de predicados**. Representa os dados como um conjunto de
**relações**.

> [!danger] "Relacional" NÃO vem de relacionamento entre tabelas
> Vem de **relação**, o nome matemático da tabela.
> Duas tabelas sem nenhuma FK continuam sendo modelo relacional.

## Vocabulário formal × prático

| Formal (teoria) | Prático (SQL) |
| --- | --- |
| Relação | Tabela |
| Tupla | Linha / registro |
| Atributo | Coluna / campo |
| Domínio | Tipo de dado |
| Esquema da relação | Estrutura (nome + atributos) |
| Instância | Conteúdo em um dado momento |

> [!warning] Par que a banca inverte
> **Grau** = nº de atributos (colunas)
> **Cardinalidade** = nº de tuplas (linhas)

## Propriedades da relação

- **Não há tuplas duplicadas** — a relação é um conjunto
- **Ordem das tuplas é irrelevante**
- **Ordem dos atributos é irrelevante**
- **Todo valor é atômico** — sem multivalorado nem composto (isso é a 1FN)

## Chaves

| Chave | O que é |
| --- | --- |
| Superchave | Qualquer conjunto que identifica unicamente |
| **Candidata** | Superchave **mínima** (sem atributo dispensável) |
| **Primária** | A candidata **escolhida** |
| **Alternativa** | As candidatas não escolhidas |
| **Estrangeira** | Atributo que **referencia** a PK de outra relação |

FK **não** é atributo derivado — derivado é atributo calculado.
PK **não** é necessariamente gerada pelo SGBD — isso descreve chave substituta.

## Regras de integridade

| Integridade | Regra |
| --- | --- |
| **De domínio** | Todo valor pertence ao domínio do atributo |
| **De entidade** | A PK **não pode ser nula** |
| **Referencial** | Toda FK aponta para uma PK existente **ou é nula** |

Integridade de entidade é o motivo de PK não aceitar nulo.
Referencial → ver [[1.5_Integridade_referencial]]

## Modelo Entidade-Relacionamento (MER)

Modelo **conceitual** criado por **Peter Chen (1976)**.
O **diagrama ER** é a sua representação gráfica — não é etapa posterior.

| Componente | O que é |
| --- | --- |
| **Entidade** | Objeto do mundo real com existência independente, sobre o qual se armazena informação |
| **Atributo** | Característica que descreve a entidade |
| **Relacionamento** | Associação lógica entre entidades |

> [!warning] MER × Relacional
> **MER** é conceitual, independe de SGBD, tem entidade e relacionamento.
> **Relacional** é lógico, tem relação, tupla e atributo.
> O MER **é transformado** no relacional → ver [[1-02-criacao-alteracao-modelos]]

## Análise de requisitos

**Fase** que define quais dados serão armazenados e quais serão descartados.
Evita redundância e armazenamento de informação inútil.
Antecede a modelagem conceitual.

## Álgebra relacional (base do SQL)

| Operação | O que faz |
| --- | --- |
| Seleção (σ) | Filtra **tuplas** (linhas) → `WHERE` |
| Projeção (π) | Filtra **atributos** (colunas) → `SELECT col` |
| Junção (⋈) | Combina relações por atributo comum → `JOIN` |
| União / Interseção / Diferença | Operações de conjunto |
| Produto cartesiano (×) | Todas as combinações |

> [!warning] Par que a banca inverte
> **Seleção = linhas** · **Projeção = colunas**

Junção é **operação de consulta**, não é o relacionamento em si.

## Outros objetos do banco

Índices, visões, procedimentos armazenados (SP), gatilhos (triggers), sequências.
Não fazem parte da teoria relacional — são recursos do SGBD.
