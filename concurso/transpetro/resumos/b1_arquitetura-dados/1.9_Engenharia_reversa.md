## O que é 

Basicamente trazer os dados que estão no modelo físico para o lógico, e do lógico para o conceitual. É reverter tudo o que fez
Pegar algo que estão pronto e destrincha ele ate entender como ele foi feito

## Importante quando

Quando não tem nenhum dicionario de dados do banco que atualmente esta em produção, com isso as queris ficam difíceis, e é aí que a engenharia reversa entra, ele vai voltar, ou destrinchar o sistema ate entender como ele foi construido

## Processos de engenharia

1. Identificar quais tabelas corresponden às entidades do diagrama
2. Definição de relacionamento
3. Definição de atributos
4. Identificar as chaves 

Olhar para as PK resolve a maioria dos problemas: Fator determinante -> composição de sua chave priária

### Passo 1: Identificar quais tabelas corresponden às entidades do diagrama

- Uma tabela pode corresponder:
	- Uma entidade
	- Um relacionamento N:M
	- Uma entidade especializada
	- Um atributo multivalorado

Tabelas podem ser classificadas em três tipos de acordo com sua PK:

| Regras  | Conceitos                                                                                                                       |
| :-----: | ------------------------------------------------------------------------------------------------------------------------------- |
| Regra 1 | Chave primaria composta por mais de uma chave estrangeira: implementa um relacionamento N:M                                     |
| Regra 2 | Quando a chave primaria é composta por uma chave estrangeira ou um atributo proprio                                             |
| Regra 3 | Toda chave primaria é uma chave estrangeira que representa uma entidade que forma uma especialização da entidade correspondente |
| Regra 4 | Os demais casos, que são as entidades fortes                                                                                    |

### Passo 2: Definição de relacionamento 1:1 ou 1:N

Toda chave estrangeira que não representa um relacionamento N:M, nem a uma entidade especializada representa um relacionamento 1:N ou 1:1

A regra não permite se a cardinalidade do relacionamento é 1:N ou 1:1

Para identificar qual o tipo de relacionamento, é necessario verificar o conteudo do banco de dados
