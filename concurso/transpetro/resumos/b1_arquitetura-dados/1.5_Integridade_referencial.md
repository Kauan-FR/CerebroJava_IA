## O que é

É a criação de restrições de dados usadas para manter as informações mais integras

## Integridade de domínio

É um tipo de restrição de integridade que garante que o valor inserido em uma coluna pertença ao tipo do domínio da coluna
Exemplo:
- Um funcionário quer adicionar um valor "Abacaxi" na coluna de "Valores", ele quer adicionar uma string na coluna onde só aceita double

## Integridade referencial

É um tipo de restrição de integridade que se referencia às chaves PK e FK, onde todos os dados cadastrados da tabela que possui a PK tem que refletir também na tabela que possui a FK
Exemplo:
- Em uma tabela chamada "Categorias" nos temos "Sucos e Frutas", o cliente ele tenta cadastra um produto chamado patilho(carne), esse produto pertence a categoria "Carnes", mas essa categoria ela não foi cadastrada na tabela, com isso essa inserção ocassionara em um erro, infligindo a integridade de domínio

## Integridade de vazio

Essa integridade diz se uma tabela ela possui atributos que podem ser nulos ou não
Exemplo:
- Digamos que iremos ter uma tabela de alunos em nosso banco, onde via ter todos os dados do aluno, e vai ter também o atributo email, nessas situação, ele pode colocar o email com `NOT NULL` tornado o email obrigatorio, ou não colocar nada, tornamdo o email opcional 

## Integridade de chave

Integridade que diz, que todos as chaves primarias não podem conter mais de um valor, e que esse valor tem que ser único

## Integridade definida pelo usuario

Integridade definida e criada pelo usuário





# 1.5 Integridade referencial

## O que é

Conjunto de **restrições** que o SGBD aplica para manter os dados consistentes, bimpedindo estados inválidos no banco.

## As quatro integridades

| Integridade | Garante | Implementada por |
| --- | --- | --- |
| **De domínio** | O valor pertence ao conjunto permitido do atributo | tipo de dado, `NOT NULL`, `CHECK`, `DEFAULT` |
| **De entidade** | A PK **não é nula** e **não se repete** | `PRIMARY KEY` |
| **Referencial** | Toda FK aponta para uma PK **existente**, ou é nula | `FOREIGN KEY` |
| **Definida pelo usuário** | Regra de negócio que não cabe nas anteriores | `CHECK` complexo, trigger, assertion |

> [!warning] Nomes formais
> "Integridade de vazio" → faz parte da **de domínio** (`NOT NULL`).
> "Integridade de chave" → é a **de entidade**.

### Exemplos

**Domínio** — coluna `valor` é `NUMERIC`; tentar inserir `'Abacaxi'` é rejeitado.
`NOT NULL` no `email` torna o campo obrigatório; sem ele, é opcional.

**Entidade** — tentar inserir dois produtos com o mesmo `id_produto`, ou inserir
um produto com `id_produto` nulo.

**Referencial** — `Produto(id, nome, id_categoria FK)`. Cadastrar "Patinho" com
`id_categoria = 7` quando a categoria 7 **não existe** em `Categoria` → rejeitado.

**Definida pelo usuário** — `CHECK (data_saida > data_entrada)`.

## Integridade referencial em detalhe

> [!danger] O sentido é do FILHO para o PAI
> A FK precisa apontar para uma PK existente.
> A tabela pai **não** precisa ter filhos — um departamento sem funcionário é válido.

### FK pode ser nula

Sim — significa "ainda não associado". Uma matrícula sem curso definido é válida.

**Exceção:** se a FK integra a chave primária, não pode ser nula (integridade de entidade).

### Autorreferência

FK apontando para a própria tabela:
`Empregado(id PK, nome, id_supervisor FK → Empregado.id)`
Aceita nulo — o presidente não tem supervisor.

## Ações referenciais ⭐

O que acontece com os **filhos** quando o pai é apagado ou alterado.
Definidas separadamente em `ON DELETE` e `ON UPDATE`.

| Ação | Comportamento |
| --- | --- |
| `NO ACTION` | **Bloqueia** — verifica no fim do comando. Padrão do SQL |
| `RESTRICT` | **Bloqueia** — verifica imediatamente |
| `CASCADE` | Propaga: apaga (ou atualiza) os filhos junto |
| `SET NULL` | FK dos filhos vira **nula** (a coluna precisa aceitar nulo) |
| `SET DEFAULT` | FK dos filhos recebe o valor **padrão** (que precisa existir no pai) |

```sql
FOREIGN KEY (id_departamento) REFERENCES Departamento(id_departamento)
    ON DELETE SET NULL
    ON UPDATE CASCADE
```

### Como reconhecer no enunciado

| Enunciado | Ação |
| --- | --- |
| "a operação é rejeitada" | `RESTRICT` / `NO ACTION` |
| "os registros associados também são excluídos" | `CASCADE` |
| "a coluna passa a conter valor nulo" | `SET NULL` |
| "a coluna recebe o valor padrão" | `SET DEFAULT` |

> [!warning] CASCADE não é anomalia
> É comportamento configurado, não defeito de projeto. Ver [[1.4_Normalizacao]]

> [!note] Entidade fraca usa CASCADE
> O dependente não existe sem o titular — apagar o pai deve apagar o filho.
> Ver [[1.2_Criacao_e_alteracao_dos_modelos_logicos_e_fisicos]]

## Integridade × Independência

> [!danger] Par que a banca inverte
> **Integridade** referencial → **existe** (FK aponta para PK válida)
> **Independência** referencial → **não existe** (distrator puro)
>
> Só existem duas independências: física e lógica. Ver [[1.1_Modelagem_conceitual_lógica_e_física]]
