## O que é SQL

**Structured Query Language** — linguagem padrão para definir, manipular e consultar
dados em bancos relacionais. É declarativa: você diz **o que** quer, não **como** buscar.

## As cinco sublinguagens ⭐

| Sigla | Nome | Faz | Comandos |
| --- | --- | --- | --- |
| **DDL** | Definição | Define a **estrutura** | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** | Manipulação | Altera os **dados** | `INSERT`, `UPDATE`, `DELETE` |
| **DQL** | Consulta | **Lê** os dados | `SELECT` |
| **DCL** | Controle de dados | Gerencia **permissões** | `GRANT`, `REVOKE` |
| **TCL** | Controle de transações | Gerencia **transações** | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> [!warning] Divergência sobre o SELECT
> Algumas bancas colocam `SELECT` em **DQL**; outras, em **DML**.
> Se a questão não tiver DQL nas alternativas, `SELECT` é DML.

## DDL — Definição

Define e altera a **estrutura** do banco.

| Comando | O que faz |
| --- | --- |
| `CREATE` | Cria tabela, view, índice, esquema |
| `ALTER` | Modifica a estrutura de um objeto |
| `DROP` | Remove o objeto **inteiro** (estrutura + dados) |
| `TRUNCATE` | Remove **todas as linhas**, mantém a estrutura |

> [!danger] TRUNCATE é DDL, não DML
> Parece DELETE, mas é DDL. Diferenças:
>
> | | `DELETE` (DML) | `TRUNCATE` (DDL) |
> | --- | --- | --- |
> | Apaga | linhas escolhidas (`WHERE`) | **todas** as linhas |
> | `WHERE` | aceita | não aceita |
> | Rollback | **pode** desfazer | geralmente **não** |
> | Velocidade | lenta (linha a linha) | rápida (desaloca) |
> | Reinicia auto-increment | não | sim |

> [!warning] DDL tem commit automático
> `CREATE`, `ALTER`, `DROP` gravam sozinhos na maioria dos SGBDs.
> Não dá para desfazer com `ROLLBACK`.

## DML — Manipulação

Altera os **dados** (linhas).

| Comando | O que faz |
| --- | --- |
| `INSERT` | Adiciona uma tupla à tabela |
| `UPDATE` | Altera valores de linhas existentes |
| `DELETE` | Remove linhas (aceita `WHERE`) |

DML **não** grava sozinha — precisa de `COMMIT`.

## DQL — Consulta

`SELECT` — lê dados sem alterar nada.

> [!note] Ordem de execução lógica do SELECT ⭐
> A ordem que você **escreve** não é a que o banco **executa**:
>
> | Escrita | Execução |
> | --- | --- |
> | 1. SELECT | 5. SELECT |
> | 2. FROM | 1. FROM |
> | 3. WHERE | 2. WHERE |
> | 4. GROUP BY | 3. GROUP BY |
> | 5. HAVING | 4. HAVING |
> | 6. ORDER BY | 6. ORDER BY |
>
> Por isso `WHERE` não enxerga apelido do `SELECT` (o SELECT roda depois),
> e `WHERE` filtra linha **antes** de agrupar, `HAVING` filtra **depois**.

> [!danger] WHERE × HAVING
> **WHERE** filtra **linhas**, antes do `GROUP BY`
> **HAVING** filtra **grupos**, depois do `GROUP BY` — usa funções de agregação

## DCL — Controle de dados

| Comando | O que faz |
| --- | --- |
| `GRANT` | Concede privilégio a um usuário |
| `REVOKE` | Retira privilégio |

## TCL — Controle de transações

| Comando | O que faz |
| --- | --- |
| `COMMIT` | Efetiva as alterações (torna permanente) |
| `ROLLBACK` | Desfaz até o último commit |
| `SAVEPOINT` | Marca um ponto para rollback parcial |

## Palavras-gatilho

| Enunciado diz | Sublinguagem |
| --- | --- |
| "cria/altera/remove tabela", "define estrutura" | **DDL** |
| "insere/atualiza/remove linha", "manipula dados" | **DML** |
| "consulta", "recupera dados" | **DQL** (ou DML) |
| "concede/retira permissão" | **DCL** |
| "efetiva/desfaz transação" | **TCL** |
| "apaga todas as linhas mas mantém a tabela" | `TRUNCATE` (**DDL**) |
| "filtra linhas antes de agrupar" | `WHERE` |
| "filtra grupos com função de agregação" | `HAVING` |

> [!danger] Pares que a banca inverte
> **DDL = estrutura** · **DML = dados**
> **TRUNCATE = DDL** · **DELETE = DML**
> **WHERE = linha** · **HAVING = grupo**
> **GRANT = dá** · **REVOKE = tira**
> **COMMIT = salva** · **ROLLBACK = desfaz**
