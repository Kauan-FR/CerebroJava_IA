## O que é SQL

**Structured Query Language** (Linguagem de Consulta Estruturada) — linguagem padrão para definir, manipular e consultar
dados em bancos relacionais. É declarativa: você diz **o que** quer, não **como** buscar.

## As cinco sublinguagens ⭐

| Sigla | Nome | Faz | Comandos |
| --- | --- | --- | --- |
| **DDL** | Definição | Define a **estrutura** | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** | Manipulação | Altera os **dados** | `INSERT`, `UPDATE`, `DELETE` |
| **DQL** | Consulta | **Lê** os dados | `SELECT` |
| **DCL** | Controle de dados | Gerencia **permissões** | `GRANT`, `REVOKE` |
| **TCL** | Controle de transações | Gerencia **transações** | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> [!warning] Divergência sobre o SELECT
> Algumas bancas colocam `SELECT` em **DQL**; outras, em **DML**.
> Se a questão não tiver DQL nas alternativas, `SELECT` é DML.

---

## DDL — Definição

Define e altera a **estrutura** do banco.

| Comando | O que faz |
| --- | --- |
| `CREATE` | Cria tabela, view, índice, esquema |
| `ALTER` | Modifica a estrutura de um objeto |
| `DROP` | Remove o objeto **inteiro** (estrutura + dados) |
| `TRUNCATE` | Remove **todas as linhas**, mantém a estrutura |

> [!danger] TRUNCATE é DDL, não DML
> Parece DELETE, mas é DDL. Diferenças:
>
> | | `DELETE` (DML) | `TRUNCATE` (DDL) |
> | --- | --- | --- |
> | Apaga | linhas escolhidas (`WHERE`) | **todas** as linhas |
> | `WHERE` | aceita | não aceita |
> | Rollback | **pode** desfazer | geralmente **não** |
> | Velocidade | lenta (linha a linha) | rápida (desaloca) |
> | Reinicia auto-increment | não | sim |

> [!warning] DDL tem commit automático
> `CREATE`, `ALTER`, `DROP` gravam sozinhos na maioria dos SGBDs.
> Não dá para desfazer com `ROLLBACK`.

## DML — Manipulação

Altera os **dados** (linhas).

| Comando | O que faz |
| --- | --- |
| `INSERT` | Adiciona uma tupla à tabela |
| `UPDATE` | Altera valores de linhas existentes |
| `DELETE` | Remove linhas (aceita `WHERE`) |

DML **não** grava sozinha — precisa de `COMMIT`.

## DQL — Consulta

`SELECT` — lê dados sem alterar nada.

> [!note] Ordem de execução lógica do SELECT ⭐
> A ordem que você **escreve** não é a que o banco **executa**:
>
> | Escrita | Execução |
> | --- | --- |
> | 1. SELECT | 5. SELECT |
> | 2. FROM | 1. FROM |
> | 3. WHERE | 2. WHERE |
> | 4. GROUP BY | 3. GROUP BY |
> | 5. HAVING | 4. HAVING |
> | 6. ORDER BY | 6. ORDER BY |
>
> Por isso `WHERE` não enxerga apelido do `SELECT` (o SELECT roda depois),
> e `WHERE` filtra linha **antes** de agrupar, `HAVING` filtra **depois**.

> [!danger] WHERE × HAVING
> **WHERE** filtra **linhas**, antes do `GROUP BY`
> **HAVING** filtra **grupos**, depois do `GROUP BY` — usa funções de agregação

## DCL — Controle de dados

| Comando | O que faz |
| --- | --- |
| `GRANT` | Concede privilégio a um usuário |
| `REVOKE` | Retira privilégio |

## TCL — Controle de transações

| Comando | O que faz |
| --- | --- |
| `COMMIT` | Efetiva as alterações (torna permanente) |
| `ROLLBACK` | Desfaz até o último commit |
| `SAVEPOINT` | Marca um ponto para rollback parcial |

Liga com ACID → [[1.14_ACID]] e transações → [[1.16_Transacoes]]

## Palavras-gatilho

| Enunciado diz | Sublinguagem |
| --- | --- |
| "cria/altera/remove tabela", "define estrutura" | **DDL** |
| "insere/atualiza/remove linha", "manipula dados" | **DML** |
| "consulta", "recupera dados" | **DQL** (ou DML) |
| "concede/retira permissão" | **DCL** |
| "efetiva/desfaz transação" | **TCL** |
| "apaga todas as linhas mas mantém a tabela" | `TRUNCATE` (**DDL**) |
| "filtra linhas antes de agrupar" | `WHERE` |
| "filtra grupos com função de agregação" | `HAVING` |

> [!danger] Pares que a banca inverte
> **DDL = estrutura** · **DML = dados**
> **TRUNCATE = DDL** · **DELETE = DML**
> **WHERE = linha** · **HAVING = grupo**
> **GRANT = dá** · **REVOKE = tira**
> **COMMIT = salva** · **ROLLBACK = desfaz**

## COUNT — a regra do nulo

```sql
SELECT COUNT(*), COUNT(ID_Depto), COUNT(Salario) FROM Funcionario;
```
- `COUNT(*)` → **5** (conta linhas, nulo incluído)
- `COUNT(ID_Depto)` → **4** (Diego é nulo, não conta)
- `COUNT(Salario)` → **4** (Elisa é nula, não conta)

**Regra:** só `COUNT(*)` conta nulo. Todo o resto de agregação ignora nulo.

## AVG, SUM — ignoram nulo

```sql
SELECT AVG(Salario) FROM Funcionario;
```
Soma 5000+4000+6000+3000 = 18000, divide por **4** (não 5 — Elisa é nula) = **4500**.

> O nulo não vira zero. Ele é **excluído** da conta. Por isso a média é sobre 4, não 5.

## INNER JOIN — só quem casa dos dois lados

```sql
SELECT F.Nome, D.Nome
FROM Funcionario F
INNER JOIN Departamento D ON F.ID_Depto = D.ID_Depto;
```
Executando linha a linha:
| Funcionário | ID_Depto | Casa? |
| --- | --- | --- |
| Ana | 10 | ✅ Vendas |
| Bruno | 20 | ✅ TI |
| Carla | 10 | ✅ Vendas |
| Diego | nulo | ❌ nulo não casa |
| Elisa | 30 | ❌ 30 não existe |

Resultado: **3 linhas**. Depto 40 (RH) também some — não tem funcionário.

## LEFT JOIN — preserva a esquerda

```sql
SELECT D.Nome, F.Nome
FROM Departamento D
LEFT JOIN Funcionario F ON D.ID_Depto = F.ID_Depto;
```
Todos os departamentos aparecem. RH (40) vem com Funcionário **nulo**.

## Achar AUSÊNCIA — LEFT JOIN + IS NULL

```sql
SELECT D.Nome
FROM Departamento D
LEFT JOIN Funcionario F ON D.ID_Depto = F.ID_Depto
WHERE F.Matricula IS NULL;
```
Só **RH** — o departamento que não casou vem com Matricula nula.

> `IS NULL` isola quem **não** tem par. `IS NOT NULL` traria o oposto.

## GROUP BY + HAVING — filtrar grupos

```sql
SELECT ID_Depto, COUNT(*) FROM Funcionario
GROUP BY ID_Depto
HAVING COUNT(*) > 1;
```
| Grupo | Linhas | Passa em >1? |
| --- | --- | --- |
| 10 | Ana, Carla = 2 | ✅ |
| 20 | Bruno = 1 | ❌ |
| 30 | Elisa = 1 | ❌ |
| nulo | Diego = 1 | ❌ |

Resultado: **só o 10**. O GROUP BY agrupa os nulos juntos (único caso em que nulos são "iguais").

## UNION × UNION ALL

```sql
SELECT Cidade FROM Cliente
UNION           -- elimina duplicata (mais lento)
SELECT Cidade FROM Fornecedor;
```
`UNION ALL` mantém as repetidas e é mais rápido (só empilha).

## Autojunção — subir na hierarquia

```sql
-- chefe do chefe de Ana
SELECT e2.chefe
FROM Empregado e1
INNER JOIN Empregado e2 ON e1.chefe = e2.empregado
WHERE e1.empregado = 'Ana';
```
1. e1 = (Ana, Bruno) → e1.chefe = Bruno
2. junção acha e2 = (Bruno, Diego)
3. e2.chefe = **Diego**

> `e1` = onde começo · `e2` = um nível acima · retornar e2 sobe dois níveis.

## EXISTS — "tem ao menos um"

```sql
SELECT Nome FROM Cliente C
WHERE EXISTS (SELECT 1 FROM Pedido P WHERE P.ID_Cliente = C.ID_Cliente);
```
Traz clientes que têm **pelo menos um** pedido. `NOT EXISTS` traz os sem pedido.

## LIKE — padrão de texto

```sql
WHERE Cidade LIKE 'S%'    -- começa com S
WHERE Cidade LIKE '%S'    -- termina com S
WHERE Cidade LIKE '%S%'   -- contém S
WHERE Cidade LIKE 'S_'    -- S + exatamente 1 caractere
```
`%` = qualquer quantidade · `_` = exatamente um caractere

## ORDER BY

```sql
ORDER BY Nome DESC    -- decrescente (Z→A)
ORDER BY Nome ASC     -- crescente (padrão)
```
