## O que é

Verificar se o modelo está **correto, completo e adequado** antes de virar banco.
Erro de modelo descoberto em produção custa muito mais caro que corrigido no papel.

## Critérios de qualidade ⭐

O que a banca cobra:

| Critério | Pergunta que ele responde |
| --- | --- |
| **Correção** | O modelo obedece às regras do modelo relacional? Chaves, integridade, formas normais |
| **Completude** | Todos os requisitos estão representados? Falta alguma entidade ou atributo? |
| **Consistência** | Há contradição interna? O mesmo conceito aparece com dois nomes? |
| **Não redundância** | O mesmo fato está guardado duas vezes sem motivo? |
| **Minimalidade** | Existe algo que não é usado por ninguém? |
| **Legibilidade** | Nomes claros, padrão de nomenclatura, diagrama compreensível |
| **Flexibilidade** | Aguenta mudança futura sem redesenho? |
| **Aderência ao negócio** | Um especialista do negócio reconhece o modelo? |

## Os três pilares

| Pilar | Verifica |
| --- | --- |
| **Negócio** | O modelo representa as regras e processos reais? As entidades fazem sentido para o usuário? |
| **Técnico** | Tipos de dados adequados, chaves corretas, normalização (ou desnormalização) justificada, desempenho, escalabilidade |
| **Governança** | LGPD atendida, dados pessoais e sensíveis classificados, metadados documentados, responsável definido |

## Como se avalia na prática

| Técnica | O que é |
| --- | --- |
| **Revisão por pares** (walkthrough) | Outro modelador percorre o modelo procurando furo |
| **Validação com o usuário** | O especialista do negócio confirma se o modelo bate com a realidade |
| **Verificação de formas normais** | Confere 1FN, 2FN, 3FN — ou justifica a desnormalização |
| **Teste com dados reais** | Carrega uma amostra e vê se as regras se sustentam |
| **Checagem de nomenclatura** | Padrão de nomes consistente em todo o modelo |

## Verificação × Validação ⭐

> [!danger] Par que a banca inverte
> **Verificação** — "estamos construindo o produto **certo**?"
> Confere contra a **especificação**. É técnico: formas normais, chaves, integridade.
>
> **Validação** — "estamos construindo o produto **correto para o negócio**?"
> Confere contra a **necessidade real**. É com o usuário.
>
> Verificação olha para dentro do modelo. Validação olha para fora, para o negócio.
