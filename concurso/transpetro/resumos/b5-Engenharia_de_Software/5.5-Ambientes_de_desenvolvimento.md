## Os ambientes ⭐

| Ambiente | Para quê | Dados |
| --- | --- | --- |
| **Desenvolvimento** | Codificar e testar isoladamente; errar sem afetar ninguém | Fictícios |
| **Teste / QA** | Equipe de teste executa os testes de sistema | Fictícios ou mascarados |
| **Homologação (staging)** | **Usuário/cliente valida** antes da liberação; **espelha a produção** | Próximos dos reais, mascarados |
| **Produção** | Uso real pelo usuário final | **Reais** |

> [!danger] Par invertido — teste × homologação
> **Teste = a equipe técnica procura defeito.**
> **Homologação = o usuário aprova para liberar** (é onde roda o teste de
> aceitação — ligação direta com [[5.4-Verificação_validação_e_teste]]).

> [!warning] Por que homologação espelha a produção
> Se a configuração for diferente, algo que passou na homologação pode falhar
> em produção. O valor dela está em ser **igual**.

## IDE ⭐

Ambiente integrado que reúne num só lugar: **editor**, **compilador/interpretador**,
**depurador (debugger)**, autocompletar, refatoração e integração com controle de
versão. Ex.: Eclipse, IntelliJ, VS Code, NetBeans.

**Depurador:** executa passo a passo, com **breakpoints**, inspecionando variáveis.

## Controle de versão ⭐⭐

> [!danger] Par invertido — centralizado × distribuído
> | | **Centralizado** | **Distribuído** |
> | --- | --- | --- |
> | Repositório | Um só, no servidor | **Cada máquina tem cópia completa** com histórico |
> | Offline | Não commita | **Commita localmente** |
> | Exemplos | SVN, CVS | **Git**, Mercurial |

---
### Comandos Git mais cobrados

| Comando | Faz |
| --- | --- |
| `clone` | Copia o repositório remoto inteiro para a máquina |
| `add` | Coloca a alteração na **staging area** |
| `commit` | Grava no repositório **local** |
| `push` | Envia os commits locais para o **remoto** |
| `fetch` | **Baixa** do remoto **sem integrar** |
| `pull` | **fetch + merge** — baixa e integra |
| `branch` | Cria/lista ramificações |
| `checkout` / `switch` | Troca de branch |
| `merge` | Integra um branch no outro, gerando commit de merge |
| `rebase` | Reaplica os commits sobre outra base — histórico **linear** |
| `stash` | Guarda alterações temporariamente sem commitar |
| `status` / `log` | Estado atual / histórico |

> [!danger] Par invertido — fetch × pull
> **fetch = só baixa. pull = baixa e junta.** `pull = fetch + merge`.

> [!danger] Par invertido — commit × push
> **commit = grava local. push = manda pro remoto.** Commit não sai da máquina.

> [!danger] Par invertido — merge × rebase
> **merge preserva o histórico** (cria commit de merge).
> **rebase reescreve** para deixar linear.

## Gerência de configuração

Controla a evolução dos artefatos. **Item de configuração** = qualquer artefato
controlado (código, documento, script). **Baseline** = versão aprovada de
referência. Atividades: identificação, **controle de versão**, **controle de
mudança**, auditoria, relato de status.

## CI / CD e DevOps ⭐⭐

| Prática | O que faz |
| --- | --- |
| **Integração contínua (CI)** | Cada commit dispara **build + testes automatizados**; integra com frequência |
| **Entrega contínua (continuous delivery)** | Software **sempre pronto** para ir à produção; a liberação é **decisão manual** |
| **Implantação contínua (continuous deployment)** | Todo commit aprovado nos testes vai para produção **automaticamente** |

> [!danger] Par invertido — delivery × deployment
> **Delivery = pronto, mas alguém aperta o botão.**
> **Deployment = vai sozinho para produção.**
> Mnemônico: **deploy**ment **deploya** sozinho.

**Pipeline:** sequência automatizada commit → build → teste → implantação.

**DevOps:** cultura e prática que **une desenvolvimento e operações**, com
automação, colaboração e entrega frequente. Não é ferramenta nem cargo.

## 7. Container × máquina virtual ⭐

> [!danger] Par invertido — container × VM
> | | **Container (Docker)** | **Máquina virtual** |
> | --- | --- | --- |
> | Virtualiza | O **sistema operacional** — compartilha o kernel do host | O **hardware** — cada VM tem SO completo |
> | Peso | Leve, sobe em segundos | Pesada, sobe em minutos |
> | Camada | Engine de container | **Hypervisor** |
>
> Resolve o "na minha máquina funciona": o ambiente vai **empacotado** junto.

**Orquestração** (Kubernetes): gerencia muitos containers — escala, reinicia,
distribui.
