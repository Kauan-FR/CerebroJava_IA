## Análise estruturada — DFD ⭐⭐

**DFD (Diagrama de Fluxo de Dados)** — mostra como o dado **flui e é transformado**
pelos processos. Quatro elementos, só quatro:

| Elemento | O que representa |
| --- | --- |
| **Processo** (círculo/bolha ou retângulo arredondado) | Transforma o dado |
| **Fluxo de dados** (seta) | O dado em movimento |
| **Depósito / armazenamento** (duas linhas paralelas) | O dado em repouso |
| **Entidade externa** (retângulo) | Origem ou destino **fora** do sistema |

**Diagrama de contexto** = DFD de **nível 0**: o sistema como **um único processo**
com suas entidades externas. Depois se faz a **explosão/refinamento** em níveis 1, 2…

> [!warning] Regra de balanceamento
> Os fluxos que entram e saem de um processo refinado devem ser os mesmos do nível
> acima. Se muda, o DFD está desbalanceado.

> [!danger] Par invertido — DFD × DER
> **DFD = função** (o que o sistema faz com o dado).
> **DER/MER = dados** (a estrutura, entidade e relacionamento — ver [[modelo-er]]).
> O DFD **não** mostra estrutura de dado; o DER **não** mostra processo.

Outras técnicas estruturadas: **dicionário de dados** (define cada dado do DFD),
**português estruturado**, **tabela e árvore de decisão**.

## 11. Pilares da orientação a objetos ⭐

| Pilar | O que é |
| --- | --- |
| **Abstração** | Representar só o que importa do mundo real |
| **Encapsulamento** | Esconder o estado interno; acesso só pela interface pública |
| **Herança** | Subclasse recebe atributos e comportamento da superclasse |
| **Polimorfismo** | Mesma mensagem, respostas diferentes conforme o objeto |

| Termo | Significado |
| --- | --- |
| **Classe** | Molde / modelo |
| **Objeto** | Instância da classe |
| **Mensagem** | Chamada de operação entre objetos |

## 12. UML 2.5 — classificação dos diagramas ⭐⭐

> [!danger] Par invertido — estruturais × comportamentais
> | **Estruturais (7)** | **Comportamentais (7)** |
> | --- | --- |
> | Classes | Casos de uso |
> | Objetos | Atividade |
> | Componentes | Máquina de estados |
> | Implantação (deployment) | **Sequência** ⟶ interação |
> | Pacotes | **Comunicação** ⟶ interação |
> | Estrutura composta | Tempo ⟶ interação |
> | Perfil | Visão geral da interação ⟶ interação |
>
> Os 4 de **interação** são um subgrupo dos comportamentais.
> Mnemônico: estrutural = **foto** (como é montado). Comportamental = **filme**
> (o que acontece ao longo do tempo).

### Os mais cobrados

| Diagrama | Mostra |
| --- | --- |
| **Casos de uso** | Funcionalidades vistas pelo **ator** — o que o sistema faz, não como |
| **Classes** | Classes, atributos, operações e relacionamentos — **estático** |
| **Sequência** | Troca de mensagens em ordem **temporal**, com linhas de vida |
| **Comunicação** | As **mesmas** mensagens, mas focando o **vínculo** entre objetos, sem eixo de tempo |
| **Atividade** | Fluxo de trabalho, com decisões e paralelismo (parente do BPMN) |
| **Máquina de estados** | **Um objeto** mudando de estado por eventos |

> [!danger] Par invertido — sequência × comunicação
> **Sequência = tempo** (eixo vertical, ordem visível).
> **Comunicação = conexão** (quem fala com quem; ordem só por numeração).

### Relacionamentos de caso de uso ⭐

| Relação | Significado |
| --- | --- |
| **«include»** | Comportamento **obrigatório**, sempre executado, extraído para reuso |
| **«extend»** | Comportamento **opcional/condicional**, acionado em certo ponto |
| **Generalização** | Um caso de uso (ou ator) é especialização de outro |

> [!danger] Par invertido — include × extend
> **Include = sempre. Extend = às vezes.**
> Direção inversa: *"comportamento executado apenas em condição específica" → qual?*

### Relacionamentos de classe

| Relação | Símbolo | Significado |
| --- | --- | --- |
| **Associação** | linha | Objetos se relacionam |
| **Agregação** | losango **vazio** | Parte-todo **fraca** — a parte sobrevive sem o todo |
| **Composição** | losango **cheio** | Parte-todo **forte** — a parte morre com o todo |
| **Generalização** | triângulo vazio | Herança |
| **Dependência** | seta tracejada | Uso pontual |

> [!danger] Par invertido — agregação × composição
> **Losango vazio = vínculo fraco (agregação). Losango cheio = vínculo forte
> (composição).** Cheio mata a parte junto.

## 13. Ferramentas CASE ⭐

**CASE** = Computer-Aided Software Engineering: ferramentas que apoiam as
atividades do processo.

| Categoria | Apoia |
| --- | --- |
| **Upper CASE** | Fases iniciais — planejamento, análise, modelagem |
| **Lower CASE** | Fases finais — codificação, teste, geração de código |
| **I-CASE (integrado)** | Todo o ciclo, com repositório único |

> [!danger] Par invertido — forward × reverse engineering
> **Forward (direta):** modelo → código (gera código a partir do modelo).
> **Reverse (reversa):** código ou banco existente → modelo (recupera a
> documentação do que já existe).
> **Reengenharia** = reverse + forward: entende o legado e reconstrói.
> Mnemônico: **reverse volta** do código para o desenho.
