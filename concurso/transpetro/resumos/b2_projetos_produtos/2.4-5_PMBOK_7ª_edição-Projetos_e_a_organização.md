## O que é PMBOK

**Project Management Body of Knowledge** — guia de boas práticas em gerência de
projetos, publicado pelo **PMI** (Project Management Institute). Não é metodologia;
é um **conjunto de conhecimento e boas práticas**.

## O que é um projeto

Esforço **temporário** para criar um produto, serviço ou resultado **único**.
Temporário = tem início e fim. → ver projeto × produto em [[2-01-scrum-kanban]]

## A MUDANÇA 6ª → 7ª ⭐ (o que mais cai)

| | **6ª edição** | **7ª edição** |
| --- | --- | --- |
| Baseada em | **Processos** | **Princípios** |
| Estrutura | 49 processos, 5 grupos, 10 áreas | 12 princípios, 8 domínios |
| Abordagem | Preditiva (cascata) | Adaptável (híbrida, ágil incluído) |
| Foco | "como fazer" (processos) | **entrega de valor** |
| Pergunta central | Que processo aplicar? | Que princípio orienta a decisão? |

> [!danger] A grande virada
> A 6ª diz **o que fazer** (processos). A 7ª diz **como pensar** (princípios).
> A 7ª passou a incluir ágil e híbrido, não só cascata.

## PMBOK 7ª — 12 Princípios ⭐

| Princípio | O que orienta |
| --- | --- |
| **Stewardship** | Ser diligente, respeitoso, zeloso (administração responsável) |
| **Team** | Construir uma equipe colaborativa |
| **Stakeholders** | Engajar as partes interessadas |
| **Value** | Focar no **valor** |
| **Systems thinking** (Holistic) | Pensar no sistema como um todo |
| **Leadership** | Demonstrar liderança |
| **Tailoring** | **Adaptar** ao contexto do projeto |
| **Quality** | Garantir qualidade nos processos e entregas |
| **Complexity** | Navegar a complexidade |
| **Risk** (Opportunities/Threats) | Otimizar respostas a riscos |
| **Adaptability / Resilience** | Ser adaptável e resiliente |
| **Change** | Capacitar a mudança para o estado futuro |

## PMBOK 7ª — 8 Domínios de desempenho

Stakeholders, Equipe, Abordagem de desenvolvimento e ciclo de vida, Planejamento,
Trabalho do projeto, Entrega, Medição, Incerteza.

> [!note] Princípios × Domínios
> **Princípios** = como se comportar (12) · **Domínios** = áreas onde o trabalho
> acontece (8). São coisas diferentes na mesma edição.

## PMBOK 6ª — a estrutura clássica ⭐ (Bloco 3 do edital)

### Os 5 grupos de processos

| Grupo | O que faz |
| --- | --- |
| **Iniciação** | Autoriza o projeto (termo de abertura) |
| **Planejamento** | Define escopo, cronograma, custo, plano |
| **Execução** | Realiza o trabalho |
| **Monitoramento e Controle** | Acompanha e corrige — **acontece em paralelo com todos** |
| **Encerramento** | Formaliza o fim |

> [!warning] Grupo de processo ≠ fase do projeto
> Os grupos não são etapas em sequência rígida. Monitoramento e Controle roda
> **o tempo todo**, em paralelo. E os grupos se repetem a cada fase.

### As 10 áreas de conhecimento

| Área | Cuida de |
| --- | --- |
| **Integração** | Amarrar tudo (termo de abertura, controle de mudanças) |
| **Escopo** | O que está e o que não está no projeto |
| **Cronograma** | Tempo, prazos |
| **Custos** | Orçamento |
| **Qualidade** | Padrões de qualidade |
| **Recursos** | Pessoas e materiais |
| **Comunicações** | Informação entre stakeholders |
| **Riscos** | Ameaças e oportunidades |
| **Aquisições** | Compras, contratos, fornecedores |
| **Partes interessadas** | Stakeholders |

> [!tip] Mnemônico das 10 áreas
> **Integração** é a que amarra as outras 9. Se cair "qual área integra todas",
> é Integração.
>
> 49 processos = a interseção de grupos × áreas. Não decore os 49 — decore
> os 5 grupos e as 10 áreas.

## 2.5 Projetos e a organização

### Tipos de ciclo de vida ⭐

| Tipo | Como é |
| --- | --- |
| **Preditivo** (cascata) | Escopo definido no início, fases sequenciais |
| **Adaptativo** (ágil) | Escopo evolui, iterativo e incremental |
| **Híbrido** | Combina os dois |

### Estruturas organizacionais ⭐

| Estrutura | Autoridade do gerente de projeto |
| --- | --- |
| **Funcional** | **Fraca** — o gerente funcional manda |
| **Matricial fraca** | Baixa |
| **Matricial balanceada** | Média |
| **Matricial forte** | Alta |
| **Projetizada** | **Total** — o gerente de projeto manda |

> [!danger] Par que a banca cobra
> **Funcional** → gerente de projeto tem pouco poder
> **Projetizada** → gerente de projeto tem poder total
> A matricial é o meio-termo (fraca, balanceada, forte).

### Documentos-chave

| Documento | O que é |
| --- | --- |
| **Termo de abertura** (Project Charter) | **Autoriza** o projeto, dá autoridade ao gerente. Vem da Iniciação |
| **Plano de gerenciamento** | Como o projeto será executado. Vem do Planejamento |
| **Business case** | Justificativa econômica do projeto |
