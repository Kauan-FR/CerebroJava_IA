## O que é

Descrição curta de uma funcionalidade na **linguagem do usuário**, do ponto de
vista de quem vai usar. Não é especificação detalhada — é um **lembrete para
uma conversa**.

---
## O modelo dos 3 Ws ⭐⭐

**"Como [quem], quero [o quê], para que [por quê]."**

| Parte | Responde |
| --- | --- |
| Como **[papel/persona]** | Quem |
| quero **[ação]** | O quê |
| para que **[benefício]** | Por quê — o **valor** |

Exemplo: *Como gerente de frota, quero exportar o relatório mensal em PDF, para
que eu possa enviá-lo à diretoria.*

> [!warning] O "para quê" é o mais cobrado
> É a parte que justifica o valor de negócio. História sem o benefício está
> **incompleta**.

## 3. Os 3 Cs ⭐

| C | O que é |
| --- | --- |
| **Cartão** | O texto curto da história |
| **Conversa** | O diálogo que detalha os requisitos |
| **Confirmação** | Os **critérios de aceitação** que provam que está pronta |

## 4. INVEST — critérios de uma boa história ⭐⭐

| Letra | Significa |
| --- | --- |
| **I**ndependent | Independente de outras histórias |
| **N**egotiable | Negociável, não é contrato fechado |
| **V**aluable | Entrega **valor** ao usuário |
| **E**stimable | Pode ser estimada |
| **S**mall | Pequena, cabe em uma iteração |
| **T**estable | Testável, com critério objetivo |

## 5. Critérios de aceitação

Condições objetivas que definem quando a história está concluída.

> [!danger] Par invertido — critério de aceitação × definição de pronto
> **Critério de aceitação = específico de UMA história.**
> **Definição de pronto (DoD) = regra geral, vale para TODAS as histórias**
> (ex.: código revisado, testado, documentado).

## 6. Épico e tema

**Épico** — história grande demais para uma sprint; é **quebrada** em histórias
menores.
**Tema** — agrupamento de histórias relacionadas.
