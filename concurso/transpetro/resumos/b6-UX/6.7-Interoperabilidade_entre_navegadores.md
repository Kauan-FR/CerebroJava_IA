## O que é

Capacidade de a aplicação web funcionar de forma **consistente e previsível** em
navegadores diferentes (Chrome, Firefox, Safari, Edge), versões diferentes e
dispositivos diferentes.

---
## Por que o problema existe

Cada navegador tem seu **motor de renderização** e implementa os padrões em ritmo
diferente. O mesmo código pode renderizar diferente em cada um.

---
## 3. A solução: padrões web ⭐

Seguir as especificações do **W3C** (HTML, CSS, acessibilidade) e do **ECMA**
(JavaScript). Código conforme o padrão é o que garante o mesmo comportamento em
qualquer navegador.

**Validadores do W3C** verificam se o HTML e o CSS estão conformes.

> [!warning] A pegadinha
> Alternativa que propõe "desenvolver uma versão específica para cada navegador"
> está **errada** — é o oposto de interoperabilidade. A solução é **um código
> conforme o padrão**.

## 4. Técnicas ⭐

| Técnica | O que é |
| --- | --- |
| **Degradação graciosa** | Constrói para o navegador **moderno** e garante que nos antigos ainda funcione, com menos recursos |
| **Melhoria progressiva** | Constrói uma base **simples que funciona em todos** e acrescenta recursos onde há suporte |
| **Teste cross-browser** | Testar a aplicação em cada navegador e versão suportados |
| **Polyfill** | Código que **adiciona** ao navegador antigo um recurso que ele não tem |

> [!danger] Par invertido — degradação graciosa × melhoria progressiva
> **Degradação parte do topo e desce.** **Melhoria parte da base e sobe.**
> Mnemônico: **degrada = de cima pra baixo. Melhora = de baixo pra cima.**

## 5. Ligação com acessibilidade

O princípio **Robusto** do WCAG é exatamente isto: funcionar em navegadores
diversos e com tecnologias assistivas. Ver [[6-1-acessibilidade-usabilidade]].

| Enunciado diz | É |
| --- | --- |

| "testar em cada navegador e versão suportados" | **Teste cross-browser** |
| "compatível com navegadores e tecnologias assistivas" | Princípio **Robusto** (WCAG) |
