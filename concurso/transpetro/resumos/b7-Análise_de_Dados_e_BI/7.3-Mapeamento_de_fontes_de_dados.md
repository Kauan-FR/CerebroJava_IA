## O que é

Identificar e documentar **de onde vem** cada dado que alimenta o BI: qual
sistema, qual formato, com que frequência atualiza e quem é o responsável.
É a primeira etapa antes do ETL.

---
## Tipos de fonte ⭐

| Origem | Exemplos |
| --- | --- |
| **Internas** | Sistemas transacionais (OLTP), ERP, CRM, planilhas, logs |
| **Externas** | Dados públicos, APIs, parceiros, redes sociais |

Formatos: banco relacional · arquivo (CSV, XML, JSON) · API · fluxo contínuo.

---
## O que se documenta de cada fonte ⭐

Sistema de origem · responsável (**data owner**) · formato · **frequência de
atualização** · volume · regra de negócio aplicada · **qualidade conhecida**.

---
## Linhagem de dados (data lineage) ⭐⭐

Rastreia o **caminho do dado da origem até o relatório**, registrando cada
transformação. Serve para auditar um número e para medir o impacto de uma
mudança na fonte.

> [!danger] Par invertido — linhagem × metadados
> **Metadado é "dado sobre o dado"** (o que é, tipo, formato).
> **Linhagem é o caminho** que ele percorreu e o que sofreu.

---
## Qualidade de dados ⭐

| Dimensão | Pergunta |
| --- | --- |
| **Completude** | Falta valor? |
| **Acurácia** | Corresponde à realidade? |
| **Consistência** | É igual em todas as fontes? |
| **Atualidade** | Está no tempo certo? |
| **Unicidade** | Há duplicata? |

**Fonte única de verdade:** definir qual sistema é o **dono** de cada dado,
para resolver divergência entre fontes.

> [!warning] Garbage in, garbage out
> Dado ruim na entrada produz análise ruim na saída. Dashboard bonito não
> corrige fonte errada.
